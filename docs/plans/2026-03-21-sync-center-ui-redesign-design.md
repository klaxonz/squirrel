# 同步中心 UI 重设计

## 目标

将同步中心从现有的多 tab 页面重构为高密度的监控分析台，优先解决两个问题：

- 快速判断当前同步系统是否健康
- 顺着异常信号快速下钻到运行实例与事件时间线

## 设计定位

新同步中心采用“双层驾驶舱 + 时间线分析台”模式：

- 首页负责全局态势判断
- 分析层负责异常定位与证据链查看

不再保留 `概览 / 运行历史 / 趋势分析` 三个平权 tab，也不再以订阅级列表作为首屏中心。

## 核心原则

- 高密度优先，减少留白、装饰性卡片和解释性文案
- 先判断，再下钻，不让用户自己决定该先点概览还是历史
- 首页先展示系统信号，再展示对象列表
- 趋势、运行实例、事件时间线必须形成连续下钻链路
- 复用现有后端能力，不设计当前数据面承载不了的 UI

## 页面结构

### 1. 顶部控制栏

顶部使用一行紧凑控制栏，包含：

- 页面标题
- 当前全局状态摘要
- 时间透镜：`现在 / 24h / 7d`
- 自动刷新
- 手动刷新
- 状态对账
- 最后更新时间

不保留长说明文案，不保留 tab 级导航。

### 2. 首屏态势层

首屏采用两栏压缩仪表板：

- 左侧：当前态势矩阵
- 右侧：最近变化矩阵

当前态势矩阵聚合：

- 运行中
- 排队中
- 失败待处理
- 延后执行
- 队列压力
- 待处理视频

最近变化矩阵聚合：

- 近 24h 成功率
- 失败运行数
- 最新 P95
- 恢复次数
- 波动站点数

这里以数字、状态色、短标签为主，不写大段提示文案。

### 3. 焦点层

首屏下方展示四组焦点模块，直接给异常线索：

- 异常站点
- 失败批次
- 高延迟批次
- 恢复事件

每组都采用紧凑列表，不做大卡片说明。目标是让用户一眼看到“哪里异常”，而不是先进入通用列表筛选。

### 4. 分析层

所有焦点入口统一进入分析工作区，不跳回旧的独立 tab 页面。

分析工作区固定为多栏结构：

- 左侧：对象流
- 中间：运行列表或趋势切片
- 右侧：详情摘要
- 最深层：运行详情抽屉与事件时间线

分析层需要承接以下场景：

- 按站点查看健康度、失败数、恢复数、P95 以及关联运行
- 按失败批次查看异常运行流
- 按高延迟批次查看慢运行流
- 按恢复事件查看恢复时间线

## 下钻路径

统一交互路径为：

`态势判断 -> 异常焦点 -> 分析工作区 -> 运行详情 -> 事件时间线`

约束如下：

- 首页任何异常信号都进入同一个分析工作区
- 全局时间透镜和筛选上下文在首页与分析层保持连续
- 运行详情与事件时间线是最终证据层，不再拆成新的孤立页面

## 现有组件调整策略

### 保留概念但重写布局

- `squirrel-frontend/src/components/sync-center/SyncOverviewCards.vue`
  改为紧凑指标矩阵，不再承担首页主导航
- `squirrel-frontend/src/components/sync-center/SyncItemsPanel.vue`
  降级为分析层中的订阅影响面列表
- `squirrel-frontend/src/components/sync-center/SyncRunHistoryPanel.vue`
  改造为分析层中的运行批次流
- `squirrel-frontend/src/components/sync-center/SyncTrendCharts.vue`
  改为趋势摘要与切片视图，不再以大块表格作为主入口

### 保留作为分析核心

- `squirrel-frontend/src/components/sync-center/SyncRunDetailDrawer.vue`
- `squirrel-frontend/src/components/sync-center/SyncEventTimeline.vue`

这两个组件继续作为最深层证据面板存在，但默认信息密度也要进一步压缩。

### 页面骨架重做

- `squirrel-frontend/src/views/SyncCenter.vue`

该页面从现有 tab 容器改为单页监控分析台骨架，负责：

- 全局控制栏
- 态势层
- 焦点层
- 分析层容器
- 下钻状态管理

## 信息密度规则

- 少留白
- 少大卡片
- 少说明文案
- 少重复标题
- 多用矩阵、紧凑列表、表格切片和状态条
- 首屏优先呈现判断信息，不优先呈现操作按钮

## 数据边界

本轮 UI 设计基于现有同步中心数据能力：

- overview：当前状态摘要
- recovery summary：恢复统计
- runs / run detail / run events：运行实例与时间线
- trends：时间序列与站点分布

因此本轮重点是重组信息架构和交互路径，不新增超出现有接口能力的大型新视图。

## 非目标

- 不做大屏风格深色驾驶舱
- 不做以失败订阅列表为首屏核心的操作台
- 不保留现有三 tab 平权结构
- 不引入大量提示性文案
- 不为了视觉效果增加空洞卡片
